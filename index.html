Estação 1 · 07:00

A guerra besta

Faz vinte anos que a indústria briga entre SQL e NoSQL. Cada lado ficou com metade da verdade. Lá nas montanhas, tomando café, Minas Gerais já tinha somado as duas metades.

🗄️ SQL

  • ✅ Tipos de verdade
  • ✅ Joins
  • ❌ Migration toda semana
  • ❌ O DBA está de férias
+

📄 NoSQL

  • ✅ Flexível
  • ✅ Sem migration
  • ❌ nome, name, nomeCompleto, NOME
  • ❌ Ninguém sabe o que tem dentro
=

🚂 Trem

  • ✅ Tipos de verdade
  • ✅ Joins (de trem com trem)
  • ✅ Flexível como documento
  • ✅ Nenhuma migration quebra nada
  • ✅ Acompanha café

O mineiro nunca precisou de mais de uma palavra pra classificar o universo. Cadeira é trem. Carro é trem. Sentimento é trem. Documento fiscal é trem. O mineiro inventou o tipo universal antes da ciência da computação existir.

Estação 2 · 07:30

As duas regras

A metodologia inteira cabe em duas regras. As duas são inegociáveis.

🗄️ Regra 1 · Banco de dados

Existe uma única tabela, e ela se chama trem.

schema.sql
CREATE TABLE trem (
  id          uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  trem_id     uuid REFERENCES trem(id),
  origem_id   uuid REFERENCES trem(id),
  destino_id  uuid REFERENCES trem(id),
  nome        text,
  email       text,
  preco_em_centavos bigint,
  quantidade  integer,
  embedding   vector(1536),
  criado_em   timestamptz DEFAULT now(),
  deletado_em timestamptz
  -- e quantas colunas o trem precisar.
  -- Todas opcionais.
);
⚙️ Regra 2 · Aplicação

Existe um único tipo, e ele se chama Trem.

trem.ts

Estação 4 · 08:45

Fundamentação técnica

Dez argumentos, sustentados pelo PostgreSQL, pelo TypeScript e pelas maiores empresas de tecnologia do mundo. Leia com calma e um café do lado.

🦆

Duck typing no banco

Ninguém declara o que é cliente e o que é pedido. O pedido é pedido porque tem preço. Um trem é definido pelo que ele carrega.

SELECT pedido.*
FROM trem AS cliente
JOIN trem AS pedido
  ON pedido.trem_id = cliente.id
WHERE cliente.email = 'ze@uai.com.br'
  AND pedido.preco_em_centavos IS NOT NULL;
🏢

A indústria chegou lá pela metade

  • Bigtable, HBase e Cassandra são tabelas esparsas com colunas quase sempre vazias.
  • A AWS recomenda single-table design no DynamoDB.
  • O Rails tem Single Table Inheritance há quase vinte anos.
  • O Protobuf 3 removeu os campos required.
  • No GraphQL, campo aceita nulo por padrão.

Cada um achou um pedaço. Minas achou a verdade inteira, e com café.

🙏

Toda coluna opcional é honestidade

No mundo real, todo dado pode faltar. O endereço veio sem número porque "é a casa amarela depois da venda do Seu Tião". Um NOT NULL é uma promessa que o mundo não vai cumprir.

Trem não é any. O any desiste de tipar. O Trem sabe o que pode ter, só não exige que tenha.

🔄

Migrations nunca mais quebram nada

No PostgreSQL, adicionar coluna nula sem default só mexe em metadados. É instantâneo. Cliente antigo ignora a coluna nova, cliente novo usa. Compatibilidade pra frente e pra trás, de fábrica.

ALTER TABLE trem ADD COLUMN cor text;
-- pronto. ninguém quebrou.
🫥

Nulo sai de graça

No PostgreSQL, um valor nulo gasta um bit no null bitmap da linha. O vazio no trem é quase de graça, igual ao silêncio mineiro. Pra performance, cada "entidade" ganha seu índice parcial.

CREATE INDEX trem_pedidos ON trem (trem_id)
WHERE preco_em_centavos IS NOT NULL;
🕸️

Muitos-para-muitos é trem

Um trem que liga um trem a outro trem é um trem.
INSERT INTO trem (origem_id, destino_id)
VALUES ('aluno', 'disciplina');

De quebra, a tabela vira também um banco de grafos.

🧠

Metade da Ciência da Computação resolvida

"Só existem duas coisas difíceis em Ciência da Computação: invalidação de cache e dar nome às coisas." (Phil Karlton)

Ninguém mais discute User contra Usuario, nem singular contra plural. É trem. A invalidação de cache fica pra depois.

⏱️

Onboarding em um segundo

Dev novo pergunta: "Qual é o modelo de dados?"

Resposta: "Trem."

Onboarding concluído. Pode pegar a primeira task.

🧪

Testes sem fixture

O menor trem válido é o objeto vazio. Ele compila e entra no banco. Todo teste começa dele e acrescenta só o que precisa.

const tremPrimordial: Trem = {};
INSERT INTO trem DEFAULT VALUES;
🧩

TypeScript é estrutural, e o trem também

No TypeScript, o que define um tipo é a forma, e não o nome. No trem, o que define um pedido é ter preço. Banco e linguagem pensam igual. O ORM fica com um model só e a impedância objeto-relacional some.

      Estação 9 · 11:30
      
Perguntas frequentes

    

    

      
🐘 E o limite de 1.600 colunas do PostgreSQL?
Se o seu trem precisar de mais de 1.600 colunas, ele ficou grande demais. Mas trem grande é trem bão. Converse com a comunidade do PostgreSQL. Nada de criar uma segunda tabela.

      
📐 E a normalização? E a Terceira Forma Normal?
A tabela trem está na Forma Normal Mineira, que vem depois de todas as outras: não pode haver redundância entre tabelas quando só existe uma tabela.

      
🤔 Como eu sei se um trem é um usuário ou um pedido?
Pelo que ele tem. Se tem email, é usuário. Se tem preço, é pedido. Se tem os dois, é um usuário que se vendeu. Teste no Laboratório, na Estação 5.

      
🏷️ Não seria melhor ter uma coluna tipo?
Até pode ter, é só mais uma coluna opcional. Mas pergunte a um mineiro que tipo de trem é aquele e ele vai responder: "Uai, é trem."

      
📈 Isso escala?
Escala pelo menos tanto quanto uma Kombi, e sobre a Kombi já sabemos tudo o que precisamos saber (Estação 7).

      
👥 Meu time vai aceitar?
Seu time já fala "trem" no dia a dia. Falta só admitir isso no banco de dados.
